## 2. Issues Identified and Resolved in This Review Round

### Issue 1: Multi-Texture Page Drawable Assignment Bug (`src/cli/main.py`)
- **Input**: Model with multiple texture atlas pages (e.g. 3–5 pages).
- **Expected**: In `stage_texture_packing`, each `DrawableKeyforms` object has its `texture_index` updated to match `result.placements[layer_id].page_index`, so that `Moc3Writer` serializes the correct texture page into `ArtMeshes.TextureNos` (Section 41) corresponding to `FileReferences.Textures` in `model3.json`.
- **Actual**: `d.texture_index` was never updated after packing and remained `0` for all drawables. All drawables were assigned to page 0 (`texture_00.png`) regardless of their actual atlas placement.
- **Root Cause**: `stage_texture_packing` updated `d.uvs_atlas = rm.uvs.astype(np.float32)` but omitted updating `d.texture_index = result.placements[match_id].page_index`.
- **Fix**: Added explicit lookup and assignment of `d.texture_index` from `result.placements` in `src/cli/main.py`.

### Issue 2: NaN / Inf UV Coordinates Bypass in Stage 5 Validation (`src/validator/structural_validator.py`)
- **Input**: `KeyformTable` with `uvs_atlas` containing `np.nan` or `np.inf`.
- **Expected**: `validate_stage5_textures_and_uvs` detects non-finite coordinates and reports validation failure.
- **Actual**: Due to IEEE-754 NaN comparison semantics, `np.nan < -1e-4` is `False` and `np.nan > 1.0 + 1e-4` is `False`, allowing NaNs to bypass Stage 5 bounds checking unchecked.
- **Root Cause**: Missing explicit `np.any(np.isnan(uvs)) or np.any(np.isinf(uvs))` check before range comparison.
- **Fix**: Added `np.isnan`/`np.isinf` check in Stage 5 validator and updated test assertion in `tests/test_adversarial_m4_challenger.py`.

### Issue 3: Ambiguous Array Truth Value Check in Mesh Methods (`src/core/mesh.py`)
- **Input**: Calling `Mesh.get_positions()`, `get_normals()`, `get_depths()`, `get_stiffnesses()`, or `get_weights()` when `self.vertices` is instantiated as a NumPy array.
- **Expected**: Returns empty array if empty, or array of property values.
- **Actual**: Raised `ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()`.
- **Root Cause**: Used `if not self.vertices:` which evaluates array truthiness rather than checking length.
- **Fix**: Changed all checks to `if len(self.vertices) == 0:` across `src/core/mesh.py`.
